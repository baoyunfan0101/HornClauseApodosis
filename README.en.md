## Design Idea
For a given real-world problem, its knowledge can be represented logically, transformed into clauses, and then solved by resolution.

Assuming facts are given in CNF (Conjunctive Normal Form — a conjunction of several clauses), the program can be divided into three parts:
- **Input**: Read the clause set into the computer, parse the meaning of each literal in clauses, and store them appropriately;
- **Resolution**: Repeatedly attempt to unify complementary literals from different clauses to derive new knowledge until the empty clause is produced;
- **Output**: Print the inference process from the initial clauses to the empty clause in a specific format.

In the implementation three classes are defined: `literal`, `horn`, and `resolution`, which represent a literal, a clause, and the resolution process respectively. Their structure is as follows:

```cpp
/* Definition of literal */
typedef class literal {
public:
    bool _P;    // Polarity: true - positive, false - negative
    int P;      // Predicate
    vector<pair<int, bool>> VC; // Variable/constant: true - variable, false - constant

    vector<int> findv();        // Find variables appearing in the literal
    bool operator<(literal);    // Overload "<" operator for sorting
    bool operator==(literal);   // Overload "==" operator, ignoring polarity

    void clear();
    void output(string, vector<string>, vector<string>, vector<string>);
    void output(vector<string>, vector<string>, vector<string>);
}literal;
```

```cpp
/* Definition of clause */
typedef class horn {
public:
    int id;

    vector<literal> L;   // Positive literal set
    vector<literal> _L;  // Negative literal set

    int F;               // 0 - initial clause, 1 - generated by substitution, 2 - generated by unification
    substitution F1;     // Substitution
    unification F2;      // Unification

    bool empty();
    vector<int> findv(); // Find variables in the clause
    void change(int, int);  
    vector<horn> substitute(vector<string>);  
    pair<horn, bool> operator+(horn);          
    bool operator==(horn); 

    void output(string, vector<string>, vector<string>, vector<string>);
    void output(vector<string>, vector<string>, vector<string>);
}horn;
```

```cpp
/* Definition of resolution */
typedef class resolution {
public:
    vector<horn> H;             // Clause set
    vector<string> predicate;   // Predicate set
    vector<string> variable;    // Variable set
    vector<string> constant;    // Constant set

    void resolute();

    void input();
    void output();
    void output_res(int);
}resolution;
```

## Core Algorithm
### Basic Principle of Clause Resolution
A Horn clause is a disjunction containing at most one positive literal. A Horn clause can be written as an implication, for example:
- P∧Q → R ⇔ ¬P∨¬Q∨R

The premise is the conjunction of positive literals (the body); the conclusion is a single literal (the head).

Since facts are assumed to be given in CNF, nested first-order constructs do not appear within clauses. Under this condition, two clauses that do not share variables but contain complementary literals can be resolved. The basic forms are:
- ¬P∨Q, ¬Q∨R → ¬P∨R
- ¬P∨R, P    → R

Sometimes substitution is needed before unification. For example, with substitution θ={u/G(x), v/x}, complementary literals Loves(G(x),x) and ¬Loves(u,v) can be eliminated by unification.

Let α be the formula to prove. By adding ¬α into the knowledge base and showing KB ∧ ¬α is unsatisfiable (i.e., deriving the empty clause), we prove KB ⊨ α.

### Input
The input part is implemented in the `input` method of the `resolution` class.

First, read an integer `n` representing the number of clauses; then read `n` lines, each representing one clause.

Each input line is tokenized (ignoring spaces, separated by special characters). If a token is followed by '(' it is recognized as a predicate; if it starts with '~' that indicates negation (polarity). Otherwise, tokens are classified as variable or constant by their first character (variables are assumed to start with 'x', 'y', or 'z'). Predicates, variables, and constants are added to the `predicate`, `variable`, or `constant` vectors accordingly. After parsing, the clause is constructed and added to the clause set `H`.

Internally predicates are represented as `int` (index in `predicate`), and variables/constants are represented as `pair<int,bool>` (index and a flag indicating variable/constant).

### Resolution
Resolution is implemented in the `resolute` method of the `resolution` class.

Because obtaining substitutions needed for unification can be complex, the implementation separates substitution and unification into two operations. Substitution is implemented by `horn::substitute`, while unification is implemented by overloading operator+ in `horn`.

![image](https://github.com/baoyunfan0101/HornClauseApodosis/blob/main/static/ResolutionTree.png)

The clause set `H` is treated as a queue, with `now` pointing at the head index. For each clause `H[now]`:
1. Attempt to resolve `H[now]` with every already-expanded clause `H[0..now-1]`; any newly derived clauses are appended to the tail of `H`.
2. Attempt all possible substitutions of `H[now]` and append the substituted results to the tail of `H`.
Repeat until the empty clause is derived or the queue is exhausted.

Overall this implements a BFS (Breadth-First Search) style expansion — conceptually similar to forward chaining. The main implementation code is shown below:

```cpp
void resolution::resolute()
{
	for (unsigned int now = 0; now < H.size(); ++now) {

		/* Try to resolve H[now] with H[i] (i=0..now-1) */
		for (unsigned int i = 0; i < now; ++i) {
			pair<horn, bool> temp;
			temp = H[i] + H[now];
			if (!temp.second)	// Unification failed
				continue;
			sort(temp.first.L.begin(), temp.first.L.end());
			sort(temp.first._L.begin(), temp.first._L.end());
			vector<horn>::iterator it = find(H.begin(), H.end(), temp.first);
			if (it != H.end())	// Duplicate clause already exists
				continue;
			temp.first.id = H.size();
			temp.first.F = 2;
			temp.first.F2.father1 = i;
			temp.first.F2.father2 = now;
			H.push_back(temp.first);
			if (temp.first.empty()) {	// Successfully derived empty clause
				output_res(H.size() - 1);	// Output the result
				return;
			}
		}

		/* Try all possible substitutions of H[now] */
		vector<horn> temp = H[now].substitute(constant);
		for (unsigned int i = 0; i < temp.size(); ++i) {
			vector<horn>::iterator it = find(H.begin(), H.end(), temp[i]);
			if (it != H.end())	// Duplicate clause already exists
				continue;
			temp[i].id = H.size();
			H.push_back(temp[i]);
		}
	}
}
```

### Output
The output (printing the inference trace) is implemented in `output_res` in the `resolution` class.

The function input is the index of the empty clause. By checking `horn::F` for each clause, the program can determine its parent clauses and how it was derived (initial, by substitution, or by unification). Recursively calling the routine with the parent indices prints the whole "search tree". For readability the routine performs recursion first then prints (post-order), so the traversal follows DFS (Depth-First Search). The key implementation is below:

```cpp
void resolution::output_res(int head)
{
	switch (H[head].F) {

	case 0:	// Initial clause
		cout << "(" << head << ")\t";
		H[head].output(predicate, variable, constant);
		cout << endl;
		break;

	case 1: {	// Generated by substitution
		vector<pair<int, int>> t;
		int k = head;
		while (H[k].F == 1) {
			pair<int, int> tk;
			tk.first = H[k].F1.v;
			tk.second = H[k].F1.c;
			t.push_back(tk);
			k = H[k].F1.father;
		}
		output_res(k);
		cout << "(" << head << ")\t";
		H[head].output(predicate, variable, constant);
		cout << "\t(" << k << "):{";
		for (unsigned int i = 0; i < t.size(); ++i) {
			if (i != 0)
				cout << ",";
			cout << variable[t[i].first] << "/" << constant[t[i].second];
		}
		cout << "}" << endl;
		break;
	}

	case 2:	// Generated by unification
		output_res(H[head].F2.father1);
		output_res(H[head].F2.father2);
		cout << "(" << head << ")\t";
		H[head].output(predicate, variable, constant);
		cout << "\t(" << H[head].F2.father1 << ")+(" << H[head].F2.father2 << ")" << endl;
		break;
	}
}
```

## Case Study
Attempt to solve a concrete problem using clause resolution.

---

**Murder Mystery**: In a house, a mysterious murder occurred. The following facts are known:
1. Only A, B, and C live in the house;
2. The murderer is someone who lives in the house;
3. The murderer hates the victim;
4. If A hates someone, then C does not hate that person;
5. A hates everyone except B;
6. B hates everyone who is not richer than A;
7. If A hates someone, then B also hates that person;
8. Nobody hates everyone;
9. A murder suspect cannot be richer than the victim.

For reasoning we add a commonsense fact:
10. A is not equal to B.

Question: Who is the murderer?

---

Translate the facts above into first-order logic as follows:
1. live(A)∧live(B)∧live(C)
2. ∀x  kill(x,A) → live(x)
3. ∀x,y  kill(x,y) → hate(x,y)
4. ∀x  hate(A,x) → ¬hate(C,x)
5. ∀x  ¬et(x,B) → hate(A,x)
6. ∀x  ¬richer(x,A) → hate(B,x)
7. ∀x  hate(A,x) → hate(B,x)
8. ∀x ∃y  ¬hate(x,y)
9. ∀x,y  kill(x,y) → ¬richer(x,y)
10. ¬et(A,B)

Convert the above first-order formulas into CNF:
1. live(x)
2. ¬kill(x,A)∨live(x)
3. ¬kill(x,y)∨hate(x,y)
4. ¬hate(A,x)∨¬hate(C,x)
5. et(x,B)∨hate(A,x)
6. richer(x,A)∨hate(B,x)
7. ¬hate(A,x)∨hate(B,x)
8. ¬hate(x,F(x))
9. ¬kill(x,y)∨¬richer(x,y)
10. ¬et(A,B)

Observe that predicate `live` appears only in (1) and (2), expressing x∈{A,B,C}; thus we can eliminate `live` and replace it with explicit facts. Clause (5) can be split and `et` eliminated, so (10) can be dropped. Clause (6) is not strictly a Horn clause but it does not prevent using resolution; treat it as (6). To avoid nested literals, modify (8) accordingly. The remaining formulas (3),(4),(7),(9) correspond to (2),(3),(7),(9) respectively. Additionally, to express `richer` as an anti-symmetric relation, add facts (10) and (11). Replace logical symbols: "¬" -> "~", "∨" -> "," for the program input format.

The final facts provided to the program are:
1. kill(A,A),kill(B,A),kill(C,A)
2. hate(x,y),~kill(x,y)
3. ~hate(A,x),~hate(C,x)
4. hate(A,A)
5. hate(A,C)
6. richer(x,A),hate(B,x)
7. hate(B,x),~hate(A,x)
8. ~hate(x,A),~hate(x,B),~hate(x,C)
9. ~kill(x,y),~richer(x,y)
10. ~richer(x,y),~richer(y,x)
11. ~richer(x,x)

As explained above, take α as the proposition to prove, selecting α from {kill(A,A), kill(B,A), kill(C,A)}. For example, when α = kill(A,A), we input ¬α as clause (0) together with the other facts; clause resolution derives the empty clause, and the output is written to `output.txt`.

Thus, the murderer in the "murder mystery" is **A himself**.
